# echoVault

Search your own notes by topic or question and get back the exact passages you wrote, with where they came from: which app (Obsidian or Notion), which folder, which note, which heading.

No AI-written answers. echoVault only returns your own words, word for word.

> **Status:** early build. Atlas features verified, C++ toolchain working, splitter done. Saving to Atlas, web app, and live demo not built yet. See [Progress](#progress).

## How it works

```
Your notes                 echovault ingest (C++)           MongoDB Atlas              Website (Next.js)
─────────                  ──────────────────────           ─────────────              ─────────────────
Obsidian .md files  ──┐    read notes                       passages collection        search box
                      ├──► split into passages      ──►     auto-embedded (Voyage) ◄── hybrid search
Notion pages  ────────┘    sync only what changed           vector + keyword indexes   results with citations
```

1. **Ingest** reads your notes and cuts each one into **passages** (a few paragraphs each, split at headings when there are any). It saves them to Atlas, and on re-runs only adds or removes what changed.
2. **Atlas** turns each passage into an embedding automatically, a list of numbers that captures its meaning, and keeps two search indexes: one for meaning, one for exact words.
3. **The website** runs both searches at once and merges the results (hybrid search). So a search for "mitochondria" finds the exact word, and "why am I tired after lunch" finds a note that never uses those words.

Full design: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Decisions and time budget: [`docs/PLAN.md`](docs/PLAN.md). Vocabulary: [`GLOSSARY.md`](GLOSSARY.md).

### How the splitter cuts a note

Given a note, the splitter:

1. **Removes the properties block** (the `---` section at the top) and keeps its `tags`.
2. **Starts a new passage at every heading** (`#`, `##`, …) and remembers which headings it's under: `Biology › Krebs cycle`. A `#` line inside a code block doesn't count, and neither does `#tag` (no space).
3. **Splits long sections** (over ~400 tokens, roughly 300 words) at blank lines between paragraphs. One huge paragraph stays whole rather than being cut mid-sentence.
4. **Cleans Obsidian syntax:** `[[Note]]` → `Note`, `[[Note|alias]]` → `alias`, and images and `![[embeds]]` are removed. Code blocks are left exactly as written.
5. **Records line numbers** for each passage, so results can say "lines 14–22".

Example, `echovault split lecture.md`:

```
tags: bio101 exam
4 passages

── lines 4-4 · ~9 tokens · (no heading)
Quick notes from Tuesday's lecture.

── lines 7-7 · ~7 tokens · Cell respiration
The mitochondria make ATP.

── lines 10-10 · ~6 tokens · Cell respiration › Krebs cycle
Happens in the matrix.
...
```

### What CMake does

C++ doesn't come with a built-in way to say "here are my source files, these are the libraries I need, build me a program." **CMake** fills that gap. `ingest/CMakeLists.txt` says:

- **Use C++20.**
- **Find three libraries** installed on this computer:
  - `mongocxx`: the official MongoDB C++ driver, which talks to Atlas.
  - `CURL`: makes web requests; will be used to call the Notion API.
  - `Catch2`: a testing framework.
- **Build a library and two programs:**
  - `echovault_core`: a **library** (reusable compiled code) holding the logic, starting with the splitter. Both programs below link it, so the tests check exactly the code the tool runs.
  - `echovault`, the real tool, from `src/main.cpp`.
  - `echovault_tests`, the tests, from `tests/`.
- **Register the tests** so `ctest` can run them all with one command.

Building is two steps:

1. `cmake -S . -B build` (**configure**): reads `CMakeLists.txt`, finds the libraries, and writes the actual build files into `build/`.
2. `cmake --build build` (**build**): compiles the code and links it with the libraries.

### `spike/` — the Atlas feature check

Before writing anything real, `spike/spike.mjs` checked the riskiest assumption: does Atlas's **free tier (M0)** support automatic embedding and combined (`$rankFusion`) search? It inserts 6 sample notes, builds both indexes, and runs each kind of search. **Result: everything works on M0** (details in `docs/PLAN.md` → Spike results).

## Setup

### Requirements (macOS)

```
brew install cmake mongo-cxx-driver catch2
```

Node.js is only needed for `spike/` (and later `web/`).

### Atlas

1. Create a free M0 cluster on [MongoDB Atlas](https://www.mongodb.com/atlas).
2. **Security → Network Access:** add your current IP address. Without this, connections fail with `tlsv1 alert internal error`.
3. Put your connection string in `.env` at the repo root:
   ```
   MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/
   ```

> **Free-tier gotcha:** M0 allows only **3 search indexes per cluster**, and deleted collections keep their index slots for a few minutes. Don't drop and recreate collections; clear their documents instead.

### Build and run the ingest tool

```
cd ingest
cmake -S . -B build                 # configure (once, or after changing CMakeLists.txt)
cmake --build build                 # compile
ctest --test-dir build              # run tests
env $(grep '^MONGODB_URI=' ../.env | xargs) ./build/echovault ping
./build/echovault split "path/to/some note.md"
```

### Run the spike

```
cd spike
npm install
node --env-file=../.env spike.mjs
```
