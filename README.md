# echoVault

Search your own notes by topic or question and get back the exact passages you wrote, with where they came from: which app (Obsidian or Notion), which folder, which note, which heading.

No AI-written answers. echoVault only returns your own words, word for word.

> **Status:** early build. Obsidian vaults and Notion pages can be synced to Atlas and searched. The website and live demo are not built yet. See [Progress](#progress).

## How it works

```
Your notes                 echovault ingest (C++)           MongoDB Atlas              Website (Next.js)
─────────                  ──────────────────────           ─────────────              ─────────────────
Obsidian .md files  ──┐    read notes                       passages collection        search box
                      ├──► split into passages      ──►     auto-embedded (Voyage) ◄── hybrid search
Notion pages  ────────┘    sync only what changed           vector + keyword indexes   results with citations
```

1. **Ingest** reads your notes and cuts each one into **passages** (a few paragraphs each, split at headings when there are any). It saves them to Atlas, and on re-runs only adds or removes what changed.
2. **Atlas** turns each passage into an embedding automatically, a list of numbers that captures its meaning, and keeps two search indexes: one for meaning, one for exact words.
3. **The website** runs both searches at once and merges the results (hybrid search). So a search for "mitochondria" finds the exact word, and "why am I tired after lunch" finds a note that never uses those words.

Full design: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Decisions and time budget: [`docs/PLAN.md`](docs/PLAN.md). Vocabulary: [`GLOSSARY.md`](GLOSSARY.md).

Commands so far:

| Command | What it does |
|---|---|
| `echovault ping` | Connects to Atlas using `MONGODB_URI` and prints the server version. Proves the database connection works |
| `echovault version` | Prints the libcurl version. Proves the web-request library is linked |

### How the splitter cuts a note

Given a note, the splitter:

1. **Removes the properties block** (the `---` section at the top) and keeps its `tags`.
2. **Starts a new passage at every heading** (`#`, `##`, …) and remembers which headings it's under: `Biology › Krebs cycle`. A `#` line inside a code block doesn't count, and neither does `#tag` (no space).
3. **Splits long sections** (over ~400 tokens, roughly 300 words) at blank lines between paragraphs. One huge paragraph stays whole rather than being cut mid-sentence.
4. **Cleans Obsidian syntax:** `[[Note]]` → `Note`, `[[Note|alias]]` → `alias`, and images and `![[embeds]]` are removed. Code blocks are left exactly as written.
5. **Records line numbers** for each passage, so results can say "lines 14–22".

Example, `echovault split lecture.md`:

```
tags: bio101 exam
4 passages

── lines 4-4 · ~9 tokens · (no heading)
Quick notes from Tuesday's lecture.

── lines 7-7 · ~7 tokens · Cell respiration
The mitochondria make ATP.

── lines 10-10 · ~6 tokens · Cell respiration › Krebs cycle
Happens in the matrix.
...
```

### How sync works (`echovault ingest`)

Every passage gets a **fingerprint** (a hash of its heading and text). Atlas stores the fingerprints, so on each run ingest can tell what changed without comparing text:

1. **Whole note unchanged?** (same fingerprint for the entire file) → skip it.
2. **Note changed?** Split it again and compare passage fingerprints with Atlas:
   - new fingerprint → **insert** (Atlas embeds it automatically)
   - fingerprint gone → **delete**
   - same fingerprint → **keep**; only line numbers and folder info get refreshed, and it is *not* re-embedded
3. **Note deleted from the vault?** → remove its passages.

Example run after editing one note and deleting another:

```
read 2 notes from ./my-vault (source: my-vault)
notes:    2 seen, 1 unchanged, 1 removed
passages: 2 inserted, 2 deleted, 1 kept
```

New passages become searchable a few seconds after ingest finishes, while Atlas indexes them in the background.

Atlas ends up with two collections in the `echovault` database (override with `ECHOVAULT_DB`):

- `passages`: one document per passage. What search runs on.
- `notes`: one document per note, with its full text. Used for the "skip unchanged" check and, later, the read-only note page.

### How Notion ingest works (`echovault ingest notion`)

1. **Map the workspace.** Notion's search endpoint lists every page and database the token can see, with each one's parent and last-edited time: ~7 requests for ~650 pages. From that, echoVault builds the page tree locally.
2. **Pick the pages under your roots.** Only pages beneath a `--root` page are included. A page's **Location** is the chain of page and database titles from the root down, e.g. `C++ Deep Dive › Topics`. Unnamed databases are left out.
3. **Download only what changed.** If a page's last-edited time matches what Atlas has, its content isn't fetched at all. Otherwise echoVault fetches its blocks (including blocks nested in toggles, lists, and columns) and converts them to lines.
4. **Skip unfilled templates.** Pages whose body is an exact copy of another page's (like 20 copies of a "Unit # - Lesson #" template) are skipped, and the count is printed.
5. **Sync** with the same fingerprint logic as Obsidian. Notion has no line numbers, so each passage remembers the **block** it starts in, and links can jump straight to that spot.

Notion allows ~3 requests per second, so the client waits between requests and retries if Notion says "slow down". In practice, on ~420 pages:

```
first run   notion: 423 under roots, 423 fetched, 25 duplicates skipped (1364 API requests)   8.5 min
re-run      notion: 423 under roots, 25 fetched, 398 unchanged (226 API requests)             1.5 min
```

### What CMake does

C++ doesn't come with a built-in way to say "here are my source files, these are the libraries I need, build me a program." **CMake** fills that gap. `ingest/CMakeLists.txt` says:

- **Use C++20.**
- **Find four libraries** installed on this computer:
  - `mongocxx`: the official MongoDB C++ driver, which talks to Atlas.
  - `CURL`: makes web requests; used to call the Notion API.
  - `OpenSSL`: for SHA-256 hashing. Homebrew installs it in a non-standard spot, so `CMakeLists.txt` tells CMake where to look.
  - `Catch2`: a testing framework.
- **Build a library and two programs:**
  - `echovault_core`: a **library** (reusable compiled code) with everything that doesn't touch the database or network: splitter, vault reader, hashing, diff, Notion block conversion. Both programs below link it, so the tests check exactly the code the tool runs.
  - `echovault`, the real tool, from `src/main.cpp` + `src/store.cpp` (Atlas) + `src/notion.cpp` (Notion API).
  - `echovault_tests`, the tests, from `tests/`.
- **Register the tests** so `ctest` can run them all with one command.

Building is two steps:

1. `cmake -S . -B build` (**configure**): reads `CMakeLists.txt`, finds the libraries, and writes the actual build files into `build/`.
2. `cmake --build build` (**build**): compiles the code and links it with the libraries.

### Demo notes

The public demo can't show anyone's real notes, so `demo-vault/` and `demo-notion/` hold notes from one **made-up student** in a sophomore fall semester. Every person in them is fictional.

| Folder | What's in it |
|---|---|
| `Classes/Biology` | Cell respiration, photosynthesis, enzymes, membranes, mitosis vs meiosis |
| `Classes/US History` | Constitutional Convention, Gilded Age, Reconstruction, New Deal, civil rights |
| `Classes/Intro Programming` | Python loops, recursion, lists/dicts, debugging, a word-counter project |
| `Classes/Statistics` | Center and spread, sampling bias, normal distribution, hypothesis testing, correlation |
| `Life/` | Cooking, money (budget, emergency fund, credit cards), books, guitar |
| `Daily/` | Two messy daily notes with no headings, like real ones |
| `demo-notion/` | The Notion side: semester plan, study plan, lab report, essay outline, project pages, meal prep, reading list, songs, savings |

The notes are written to **test the search**, not just fill space:

- **Messy on purpose.** Some notes have no headings, and some have tags, `[[links]]`, images, code blocks, tables, and checklists. These exercise every splitter rule.
- **Decoys.** Some words show up in notes that mean different things: *power* (statistics vs power chords vs separation of powers), *starter* (sourdough vs starter code), *cell* (biology vs spreadsheet). A plain keyword search gets fooled by these; meaning-based search shouldn't.
- **No shared words.** For some test questions, the right passage deliberately uses none of the question's words ("my fingers hurt when I play" → a passage about sore *fingertips* and *calluses*). Only meaning-based search can find those.

`docs/eval-queries.md` lists 15 test questions and the passage each should find, written **before** running any search so the answers can't be tuned. The first 6 become the example buttons on the search page.

Size: 34 Obsidian notes → 105 passages, 10 Notion pages → 40 passages.

## Setup

### Requirements (macOS)

```
brew install cmake mongo-cxx-driver catch2    # OpenSSL comes along with mongo-cxx-driver
```

Node.js is only needed for `spike/` (and later `web/`).

### Atlas

1. Create a free M0 cluster on [MongoDB Atlas](https://www.mongodb.com/atlas).
2. **Security → Network Access:** add your current IP address. Without this, connections fail with `tlsv1 alert internal error`.
3. Put your connection string in `.env` at the repo root:
   ```
   MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/
   ```

4. Create the collection and indexes (once): `echovault init` (see below).

### Notion (optional)

1. In Notion: **Settings → Connections → New connection → API token**, read-only if offered.
2. Add the token to `.env`: `NOTION_TOKEN=ntn_...` (never paste it anywhere else).
3. If your token only sees pages you share with it, open each root page → **••• → Connections** → add it.

> **Free-tier gotcha:** M0 allows only **3 search indexes per cluster**, and deleted collections keep their index slots for a few minutes. Don't drop and recreate collections; clear their documents instead. echoVault uses 2 slots.

### Build and run the ingest tool

```
cd ingest
cmake -S . -B build                 # configure (once, or after changing CMakeLists.txt)
cmake --build build                 # compile
ctest --test-dir build              # run tests
./build/echovault split "path/to/some note.md"   # preview, no database

export $(grep -E '^(MONGODB_URI|NOTION_TOKEN)=' ../.env | xargs)   # load secrets into this terminal
./build/echovault ping                           # check the connection
./build/echovault init                           # once: collection + indexes
./build/echovault ingest obsidian "path/to/vault"
./build/echovault ingest notion --root "fall 2026"
```

### Load the demo notes (separate Atlas project)

The demo uses its **own** Atlas project so the public site can never see your personal notes.

1. In Atlas, create a new project (e.g. `echovault-demo`) with a free M0 cluster, allow your IP, and add its connection string to `.env` as `DEMO_MONGODB_URI=...`.
2. Notion side (optional): make a **new free Notion workspace** just for the demo. Create a page called `Sophomore year`, then use **Import → Text & Markdown** to import the 10 files in `demo-notion/`, and drag them under `Sophomore year`. Create an API token in *that* workspace and save it as `DEMO_NOTION_TOKEN=...`.
3. Run the ingest against the demo cluster:
   ```
   cd ingest
   export MONGODB_URI=$(grep '^DEMO_MONGODB_URI=' ../.env | cut -d= -f2-)
   export NOTION_TOKEN=$(grep '^DEMO_NOTION_TOKEN=' ../.env | cut -d= -f2-)
   ./build/echovault init
   ./build/echovault ingest obsidian ../demo-vault --name demo-vault
   ./build/echovault ingest notion --root "Sophomore year" --name demo-notion
   ```

### Run the spike

```
cd spike
npm install
node --env-file=../.env spike.mjs
```
